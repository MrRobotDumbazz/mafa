# Модель-формула выявления нарушений (W3, v0.1)

База: Python + OpenCV + NumPy + Pandas + openpyxl. Ядро правил — чистый stdlib (работает без внешних пакетов; pandas/openpyxl — только на слоях экспорта/EDA, OpenCV/трекинг — на слое восприятия).

## 1. Архитектура комплекса

```
Видео → [Восприятие: детекция людей (OpenCV+YOLOX/RT-DETR), трекинг (ByteTrack), поза (MediaPipe),
         классификация клипов (VideoMAE), кадры-доказательства (ffmpeg)]
              → ПРИМИТИВЫ (model/primitives.py): события/состояния с таймкодами и уверенностью
              → ДВИЖОК НОРМ (model/engine.py + model/scenarios.py):
                   K1 действия сотрудника | K2 действия клиента | K3 обстановка
              → Violation(label, t, conf, frames) → JSON по ml_events.schema.json
```

## 2. Формула комплекса (ор-семантика)

Пусть V — видео, P — поток примитивов, S(t) — состояния обстановки.

```
Verdict(V) = D_K1(V) ∨ D_K2(V) ∨ D_K3(V)                 — хоть одно отклонение = нарушение

D_Kx(V) = ⋁_{r ∈ Rules_x} fired(r, P, S)

fired(r) = 1[condition_r(P, S) устойчиво ≥ порога r.min_dur]   (инварианты, канал K3)
fired(r) = 1[обязательный шаг r не наблюдается в окне операции к r.deadline]  (пропуск, K1/K2)
fired(r) = 1[запрещённое действие r наблюдается в окне операции]               (вторжение, K1)
```

Каждое срабатывание немедленно пишет Violation с label из каталога (`research/violation_hypotheses.yaml`), окном, уверенностью и кадрами-доказательствами. Дедупликация — cooldown по label.

Отклонение трёх родов (покрывают любые нарушения):
1. **Пропуск** (omission) — обязательный шаг нормативного плана не наблюдается;
2. **Нарушение порядка** (order) — шаг выполнен до предшественника / вне окна;
3. **Запрещённое действие/состояние** (commission/state) — то, чего не должно быть ни в одном плане.

### K2. Действия клиента (эталоны)
1. Предъявить документ в начале операции → `RECV_NO_ID` / `ISSUE_NO_ID`;
2. Передать деньги только на рабочую позицию кассира;
3. При выдаче — пересчитать деньги, не отходя от кассы → `ISSUE_NO_CLIENT_RECOUNT`;
4. Получить подтверждающий документ → `ISSUE_NO_RECEIPT`;

6. Уход без денег/документа — маркер сбоя процесса → `ANOM_CLIENT_LEFT_EMPTY`.

## 4. Связь с восприятием (следующий слой)

| Примитив | Источник | Устойчивость к ракурсу |
|---|---|---|
| ZONE_ENTER/LEAVE, роли (кассир/клиент/контролёр/инкассатор) | детекция+трекинг + **относительные зоны** (стол = область максимальной плотности пребывания кассира; дверь = точка входов) | да — зоны калибруются по траекториям, не в абсолютных пикселях |
| LEAVE_STATION | трекинг: кассир вне staff-зоны > gap | да |
| DOC_SHOW / DOC_CHECK / MONEY_TO/BAG_TO | поза (скелет): жесты передачи малого объекта между зонами | частично — ретargetинг поз |
| COUNT_MONEY / COUNT_MACHINE / AUTH_CHECK | поза + привязка к точке оборудования + классификатор клипов | средняя |
| PILE_MERGE / SORT_PILES | классификатор клипов + трекинг стопок | средняя |
| STATE_* (сейф/дверь/свет/деньги/вещи/ключ) | детектор объектов + изменение сцены (фон) | да — по относительному положению к зонам |
| THIRD_IN_STAFF / CLIENT_DEPARTS_EMPTY | трекинг+зоны+объекты в руках | да |
| OP_CLS (тип операции) | классификатор клипов (.VideoMAE) или эвристика от примитивов | — |

Confidence правила = conf(примитива) × min(1, dur/(2×min_dur)), cap 0.95. Evidence frames — до 3 таймкодов из примитивов правила.

## 5. Anomaly-слой (новые типы нарушений, FAQ 9)

`ANOM_UNKNOWN`: автоэнкодер/метрика расстояния до «нормы» на эмбеддингах клипов; превышение квантиля — кандидат на немаркированное отклонение. Подключается к тому же движку как примитив-событие.

## 6. Файлы

- `primitives.py` — типы событий/состояний от восприятия;
- `scenarios.py` — нормативные планы (шаги, инварианты, пороги) как данные;
- `engine.py` — движок: примитивы → Violation(label, t, conf, frames); OR-семантика K1∨K2∨K3;
- `selfcheck.py` — синтетические прогоны (чистые/грязные сценарии) — запуск: `python3 model/selfcheck.py` из `services/ml`.
