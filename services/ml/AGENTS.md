## Границы

- Пишешь: `services/ml/**`; владеешь контрактами `contracts/ml_events.schema.json` и `contracts/violation_catalog.yaml`.

## Задача зоны (критический путь: критерии 1–5 кейса, 80/100 баллов)

- EDA: `datasets/open/open_labels.xlsx` (метка «нарушение» + таймкод; тип не указан — определяешь сам) × 41 видео.
- Локальный пайплайн «видео → события»: детекция/поза/трекинг → тип, таймкод, уверенность, кадры-доказательства.
- Типы нарушений связать с нормативными актами РК (НБРК, adilet.zan.kz) — без выдуманных ссылок (E8; критерий 4).
- Устойчивость к смене ракурса (критерий 5). Пропуск нарушения недопустим, ложные срабатывания минимизировать (FAQ 16).
- Порядок работ — Этап 2 `PLAN.md`; интеграция с backend — Этап 4 (стык описан в `services/api/README.md`).

Только локальные модели — облако = дисквалификация (раздел 7 кейса); лица не идентифицировать (FAQ 29); звук не использовать (FAQ 28).

Перед работой — аттестация: «Работаю в зоне ml (W3)» (C3). Коммит атомарен зоне, `git add -A` запрещён — стадируется только своё (C5). Межзонное — только через контракты и файлы репо (I42). Утверждение — со ссылкой на источник или с пометкой «не проверено» (E8). Пуш/пулл — акты человека, креды не запрашивать (I48/I52).
