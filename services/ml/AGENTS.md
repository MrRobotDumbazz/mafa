# AGENTS.md — зона ml (владелец P2)

Зона ML-ядра. Работает человек **P2 — своими руками, без ИИ-агента**. Если позже в зону сядет агент, он входит здесь как **W3** (полный вход по E6, досье зоны на руках) и подчиняется этому файлу как закону.

## Границы

- Зона пишет: `services/ml/**`; владеет контрактами `contracts/ml_events.schema.json` и `contracts/violation_catalog.yaml`.
- Читает всё; чужие зоны не трогает: `services/api/` — W1, `services/web/` — W2, `tests/` — P4.
- `datasets/open/` — обучение/валидация разрешены (рамки хакатона); тестовые видео жюри — никогда.

## Задача зоны (критический путь: критерии 1–5 кейса, 80/100 баллов)

- Исследовать датасет: `datasets/open/open_labels.xlsx` (метка «нарушение» + таймкод; тип не указан — определяется самостоятельно).
- Локальный пайплайн «видео → события»: детекция/поза/трекинг → тип, таймкод, уверенность.
- Определить типы нарушений и связать каждый с нормативным актом РК (НБРК, adilet.zan.kz) — без выдуманных ссылок (E8; критерий 4).
- Устойчивость к смене ракурса (критерий 5). Приоритет метрик: пропуск нарушения недопустим, ложные срабатывания минимизировать (FAQ 16).

## Контракты

- Предоставляет: `ml_events.schema.json`, `violation_catalog.yaml` (скелеты сгенерированы при Genesis — финализирует зона ml). До готовности зоны W1/W2 работают от моков (B2).
- Потребляет: `contracts/api.openapi.yaml` (только чтение).

## Правила

Только локальные модели — облако = дисквалификация (раздел 7 кейса); лица не идентифицировать (FAQ 29); звук не использовать (FAQ 28). Межзонное — через файлы репо (I42); пуш — акт человека (I48). Для агента W3 (если появится): аттестация C3, стейджинг только своего (C5), права R1–R5 (канон 6.2), тариф (канон 6.3).

Закон: `docs/ztacp-pattern.md` (1.0-rc14).
