## 1. Резюме

1. Полный локальный конвейер `.mov → детекция → трекинг → поза → open-vocab объекты → rule-engine → события (label + пункт НПРК + confidence + JPEG-кадры) → JSON v1` собран, **встроен в backend (SELFCHECK PASSED)** и работает на всех 42 видео.
2. **Holdout v4: recall 1.00 (FN=0), precision 0.54, таймкод ±10 с — 5/7.** Требование FAQ 16 «пропуск нарушения недопустим» выполнено впервые (v1 давал recall 0.57).
3. Цена recall-приоритета — FPR 1.0 на чистых; три источника FP локализованы и имеют конкретные ручки тюнинга (§7). Прогон полного holdout ≈ 25–35 мин CPU — тюнинг вынесен в план v5.
4. Всё — open-source и локально: YOLOv5n + OWLv2-q4f16 + RTMPose-s (HuggingFace) + чистый Python; облако не используется (раздел 7 кейса).

## 4. Новые правила v4 (чего не было в v1–v3)

1. **RECV_NO_ID**: окно приёма (≥6 с) без ни одного наблюдения ID-документа (OWLv2 «identity card») → нарушение п. 19-1 № 231. Ловит X-2/X-17 точно.
2. **ISSUE_NO_RECOUNT**: окно выдачи без COUNT_MONEY (осцилляция запястий кассира ≥14 смен направления) → п. 31-4.
3. **Реальная дверь от OWLv2** (медианный бокс за видео) гейтит сценовое правило: персистентная смена состояния внутри дверного бокса → ROOM_DOOR_OPEN (X-20/X-30/X-33).
4. **KEY/MONEY на столе** (не на человеке) → STATE_KEY_TABLE / подтверждение STATE_MONEY_TABLE.
5. Каналы включаются автоматически при наличии весов; без них run.py деградирует до classic-режима.

## 6. FP-разбор (18 чистых, v4; всё сработало на 18/18 — FPR 1.0)

| Семейство | чистых видео | Причина | Ручка тюнинга |
|---|---|---|---|
| CASH_MIXED_WORN / RECV_MIXED_FUNDS | 9 / 3 | слияние кластеров срабатывает на любые соседние вещи (сумки, документы) | cooldown 6→15 с; требовать ≥2 с совместной персистентности; только малые кластеры (деньги-размер) |
| RECV_NO_ID | 9 | OWLv2 не видит документ (ракурс сверху, мелкий объект) → omission-правило ложно | окно 6→12 с; требовать ≥2 OWL-сэмпла в окне; confidence-калибровка |
| ROOM_DOOR_OPEN | 7 | смена состояния у двери (люди выходят, дверь закрывается за кадр среза bg) | проверка конечного состояния (последние 2 с видео); амплитуда изменения ≥X |
| RECV_FUNDS_ACCESSIBLE | 3 | стат-кластеры при клиенте — его же сумка на столе | исключать кластеры в client-зоне; min overlap 8→15 с |

Все ручки — параметры emit/engine без изменения архитектуры; тюнинг только на tune-наборе (B2-дисциплина holdout).

## 7. Архитектура и продукты

- `run.py`: валидация .mov (ffprobe), `--backend auto|dnn|classic`, авто-.venv; stdout JSON по `contracts/ml_events.schema.json` v1 (+`summary`: вердикт, клипы, расшифровка label'ов, норматив).
- `batch_report.py`: отчёт по загруженным видео (label → расшифровка → пункт НПА → таймкоды → кадры).
- `holdout.py`: стратифицированный split (seed 42), метрики (recall-приоритет), отчёты в `research/`.
- Движок: `model/` (K1∨K2∨K3, omission/commission/state, cooldown), каталог 35 label с пунктами ПП НБРК № 231/№ 120.
- Backend: `FORTE_PIPELINE_CMD="python3 ../ml/run.py"` → `SELFCHECK PASSED` (полный цикл upload→job→вердикт→кадры).

## 8. Ограничения (честно)

- Точный label-мэтчинг пока слабый (вердикт TP 21/22, label hit ~2/22): прокси-label'ы; вырастет с калибровкой confidence и категоризацией окон (issue vs receive).
- ROOM_LOW_LIGHT недетектируем (автоэкспозиция, доказано численно).
- OWLv2 на CPU — 5–7 с/кадр: интервал 5 с; на GPU (если даст P1) — покадрово.
- FPR 1.0 — до тюнинга v5 (см. §6).
